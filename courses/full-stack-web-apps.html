  • Take real payments with PayFast or Yoco

Who it's for

Before you start

Curriculum

8 weeks · 24 lessons · a hands-on exercise and a deliverable every week.

Week 1React fundamentals

Think in components and build interactive UIs with React.

  1. 1.1

    Modern JavaScript refresher

    Arrow functions, destructuring, modules, promises and async/await: everything React code relies on.

  2. 1.2

    Components and props

    Break a page into reusable components and pass data between them.

  3. 1.3

    State and events

    Make components interactive with useState and handle user input.

Exercise
Build a service menu component where users can pick services and see a running total.
By the end of the week
A React front end for the booking app's service selection screen.
Week 2Next.js and routing

Structure a real application with pages, layouts and server rendering.

  1. 2.1

    The App Router

    Folders become routes. Build layouts, nested pages and dynamic routes.

  2. 2.2

    Server and client components

    What runs on the server and what runs in the browser, and why it matters for speed.

  3. 2.3

    Loading data

    Fetch data on the server and handle loading and error states properly.

Exercise
Add a services page, a service detail page and a shared layout with navigation.
By the end of the week
A multi-page Next.js app deployed as a preview on Vercel.
Week 3Databases with Postgres and Supabase

Store and query real data.

  1. 3.1

    Designing tables

    Plan tables for services, bookings and customers. Primary keys, relationships and data types.

  2. 3.2

    SQL essentials

    SELECT, INSERT, UPDATE, DELETE and JOIN. Enough SQL to answer real questions about your data.

  3. 3.3

    Supabase in Next.js

    Connect your app to Supabase and read and write data safely.

Exercise
Create the database schema and seed it with sample services and time slots.
By the end of the week
The app showing real services and available time slots from the database.
Week 4Users, logins and permissions

Let people sign up and make sure they only see their own data.

  1. 4.1

    Authentication

    Email and password sign-up, magic links and Google login with Supabase Auth.

  2. 4.2

    Protected pages

    Redirect logged-out users and show each user their own dashboard.

  3. 4.3

    Row Level Security

    Database rules that stop users reading other people's bookings, even if the front end has a bug.

Exercise
Add sign-up and login, plus a 'My bookings' page.
By the end of the week
Working accounts where each user sees only their own bookings.
Week 5Building your own API

Write back-end logic that the front end and other services can call.

  1. 5.1

    Route handlers

    Create API endpoints in Next.js for creating, updating and cancelling bookings.

  2. 5.2

    Validation

    Never trust input. Validate requests with Zod and return clear error messages.

  3. 5.3

    Server actions

    Handle forms without writing a separate API, and know when to use which approach.

Exercise
Build the booking flow: choose a service, pick a time, confirm.
By the end of the week
End-to-end booking that stops two people booking the same slot.
Week 6Payments with PayFast and Yoco

Take real money in rands.

  1. 6.1

    How online payments work

    Checkout flows, sandbox vs live mode, fees and what South African payment providers need from you.

  2. 6.2

    Integrating PayFast or Yoco

    Send customers to checkout and bring them back to the right page afterwards.

  3. 6.3

    Payment webhooks

    Confirm payments server-side so a booking is only confirmed once the money has actually arrived.

Exercise
Require a deposit before a booking is confirmed.
By the end of the week
Paid bookings working end to end in sandbox mode.
Week 7Quality, speed and security

Make your app reliable enough for real customers.

  1. 7.1

    Testing what matters

    Test the booking and payment logic that would cost money if it broke.

  2. 7.2

    Performance

    Image optimisation, caching and Lighthouse scores. Make it fast on a mid-range phone on mobile data.

  3. 7.3

    Security basics

    Environment variables, secrets, rate limiting and the common mistakes that leak data.

Exercise
Get a Lighthouse score of 90+ on mobile and fix every issue a code review finds.
By the end of the week
A tested, optimised app with a clean security checklist.
Week 8Launch

Ship it and show it.

  1. 8.1

    Production deployment

    Environment set-up, a custom domain and switching payments to live mode.

  2. 8.2

    Monitoring

    Error tracking, logs and analytics so you find out about problems before your users do.

  3. 8.3

    Demo day prep

    Present your app like you're pitching it to a client.

Exercise
Run a full test booking on the live site.
By the end of the week
Your booking app live in production.

Final project

A complete booking app for a real or imagined Cape Town business, such as a barber, gym, studio or tour operator. It needs user accounts, a booking calendar, deposits via PayFast or Yoco, an admin view, and a production deployment. You demo it live on demo day.
